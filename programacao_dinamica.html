A ideia central da programação dinâmica é simples: identificar subproblemas sobrepostos (aqui, os mesmos valores de F(k) aparecendo várias vezes na árvore) e guardar o resultado de cada um na primeira vez em que é calculado. Isso troca uma complexidade exponencial por uma linear — a diferença fica mais evidente quanto maior o n.

Problema: empilhar caixas para conseguir a maior altura possível. Uma caixa só pode ficar em cima de outra se for estritamente mais estreita. A decisão em cada caixa é: vale mais a pena ficar sozinha no topo, ou apoiar em cima de alguma pilha já calculada?

1 Ordenar as caixas

Sem ordenar, não dá pra saber quais caixas já são "candidatas válidas" para apoiar uma nova caixa. Ordenando por largura decrescente, ao chegar em cada caixa todas as que poderiam estar embaixo dela já foram processadas.

Ordem original (aleatória).

2 Definir o subproblema

melhor(i) = maior altura de pilha possível tendo a caixa i como base. Para calcular, olho todas as caixas mais largas que já viraram base de alguma pilha calculada antes, pego a melhor delas e empilho a caixa i em cima.

melhor(i) = altura(i) + max( melhor(j) | largura(j) > largura(i), j já processado )

3 Resolver reaproveitando subproblemas

Cada caixa processada vira uma entrada no memo. Caixas seguintes consultam esse memo em vez de recalcular a pilha inteira a partir do zero — é por isso que o número de consultas cresce, mas o número de cálculos novos não.

Esse é o mesmo padrão do Fibonacci, só que aplicado a um problema de decisão: em vez de somar dois valores anteriores, cada caixa escolhe o melhor entre vários subproblemas já resolvidos. Sem memoização, recalcular "qual a melhor pilha possível a partir daqui" para cada caixa, em cada chamada recursiva, também cresceria exponencialmente — com a tabela, cada caixa é processada uma única vez.

Uma fábrica precisa decidir quanto produzir a cada mês para atender a demanda conhecida, considerando custo de produção, custo de manter estoque, e que é sempre possível produzir antecipadamente para os meses seguintes. A decisão em cada mês é: produzir só o necessário agora, ou produzir mais e guardar em estoque para economizar no futuro?

1 Configurar os dados do problema

Demanda conhecida, custo de produção e custo de estoque variam mês a mês.

2 Definir o subproblema

melhor(mês) = menor custo possível para atender toda a demanda do mês até o fim do horizonte, partindo de estoque zero nesse mês.

melhor(m) = mín. sobre k ≥ m de [ custo de produzir em m cobrindo m..k + estoque acumulado + melhor(k+1) ]

3 Resolver de trás para frente, reaproveitando subproblemas

Como a decisão de um mês depende do custo dos meses seguintes, calculamos primeiro o último mês, depois o penúltimo, e assim por diante — cada mês processado consulta o resultado já memoizado dos meses seguintes em vez de recalculá-lo do zero.

O problema da mochila 0-1 é o exemplo canônico da equação de Bellman: dado um conjunto de itens com peso e valor, e uma mochila de capacidade W, quais itens incluir para maximizar o valor total sem exceder a capacidade? Cada item pode ser incluído (1) ou não (0) — daí o "0-1". Ao contrário de Fibonacci (1D), o estado aqui é bidimensional: (item, capacidade).

Equação de Bellman

Estado (i, c) — item i e capacidade restante c
Função valor V(i, c) = maior valor com itens 1..i e capacidade c
Base V(0, c) = 0  ∀c
V(i, c) = V(i−1, c) se wᵢ > c V(i, c) = max( V(i−1, c), vᵢ + V(i−1, c−wᵢ) ) se wᵢ ≤ c

Dois casos: item muito pesado → só pular. Caso contrário, o melhor entre pular (linha acima, mesma coluna) e tomar (valor do item + melhor resultado com a capacidade restante).

Backtracking — quais itens foram escolhidos?

A tabela guarda valores, não decisões. Para saber quais itens entraram, percorremos de baixo para cima: se V(i, c) ≠ V(i−1, c), o item i foi tomado; subtraímos wᵢ de c e continuamos.

Itens na mochila

O estado bidimensional (item, capacidade) é o que torna o knapsack mais rico que Fibonacci: em vez de uma linha, a tabela é uma grade. A equação de Bellman é a mesma abstração — V(estado) depende de V(estados menores) — apenas a definição de "estado" e "transição" muda. Nos outros exemplos desta página: Fibonacci tem estado 1D (índice n); pilha de caixas tem estado 1D (caixa base); planejamento de produção tem estado 1D (mês). Knapsack é o salto natural para estados 2D.
